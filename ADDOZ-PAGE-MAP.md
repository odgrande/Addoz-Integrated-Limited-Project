# ADDOZ page map

The routes of the ADDOZ Next.js 16 prototype (Directives 008 and 009). Every route uses sample data. Nothing is connected to a backend yet.
Columns: purpose, audience, key components, content source, prototype state and future backend dependency.

## Core, jobs and content pages

| Route | Purpose | Audience | Key components | Content source | Prototype state | Future backend dependency |
|---|---|---|---|---|---|---|
| `/` | Homepage: brand story from hero through journey, discovery, intelligence, employers, community and newsletter | Candidates and employers (first visit) | `Homepage` → `SiteHeader`, `Hero`, `OpportunityTicker`, `CareerJourney`, `JobDiscovery`, `Explore`, `CareerIntelligence`, `EmployerSection`, `Community`, `Newsletter`, `SiteFooter` | `components/addoz/*`, `features/jobs/data.ts`, `lib/demo-jobs.ts` (`sourceSite` only, in `Community`) | Complete (Directive 008); unchanged in 009 | Live featured jobs, newsletter signup endpoint |
| `/jobs` | Search and filter all roles | Candidates | `JobsBrowser` (search, filters, job cards, saved jobs) | `features/jobs/data.ts`, `features/jobs/saved-jobs.ts` (browser-local saves) | Client-side filtering over sample jobs | Jobs search API, saved jobs tied to candidate accounts |
| `/jobs/[slug]` | One role: details, company, related roles | Candidates evaluating a role | `JobDetail` | `features/jobs/data.ts` (`getJob`, `relatedJobs`), `features/companies/data.ts` (`getCompany`) | `generateStaticParams` for every sample job; `robots: noindex`; replaces the retired `/jobs/[id]` route | Live job records, apply flow, application tracking |
| `/about` | Who ADDOZ is: mission, candidate process, employer proposition, tools, testimonials, contact CTA | Candidates, employers, partners | `PageHeader`, `SectionHeading`, `Reveal`, `BrandShape`, `ActionButton`, `MagneticButton` | `lib/site.ts`, `features/content/testimonials.ts`, `features/ai/tools.ts` | Static server page | None beyond CMS for copy/testimonials |
| `/contact` | Contact details and enquiry form | Candidates, employers, general enquiries | `PageHeader`, `BrandShape`, `ContactForm`, `AppLink` | `lib/site.ts` (email, phone, address) | Front-end only: the form validates locally, then hands off to a pre-filled `mailto:` link. Nothing is sent to a server | Contact/enquiry endpoint with spam protection |
| `/faq` | Common questions for candidates and employers | Candidates, employers | `PageHeader`, `Accordion`, `AppLink`, `MagneticButton` | Inline in `app/(marketing)/faq/page.tsx`, `lib/site.ts` | Static; accessible accordion | CMS-managed FAQ (optional) |
| `/privacy` | Privacy policy outline | All users | `LegalPage` | Inline section list in `page.tsx` | Placeholder: section headings with one-line summaries, each marked as pending legal review. No legal clauses were invented | Final policy text from legal review |
| `/terms` | Terms of use outline | All users | `LegalPage` | Inline section list in `page.tsx` | Placeholder: section headings and summaries only, pending legal review. No clauses were invented | Final terms text from legal review |

## Discovery: companies, categories, locations

| Route | Purpose | Audience | Components | Content source | Prototype state | Future backend dependency |
|---|---|---|---|---|---|---|
| `/companies` | Browse sample employer profiles by name, industry and location | Candidates exploring employers | `PageHeader`, `CompaniesBrowser` (SearchBar, industry chips, location select, `FilterBar`, `CompanyCard` grid, `EmptyState`), CTA `SectionHeading` | `features/companies/data.ts` (companies, companyIndustries), `features/locations/data.ts` (states/areas for the location select) | Fully client-side instant filtering, Flip reflow; companies visibly labelled sample | Real employer directory + search API once employer accounts exist |
| `/companies/[slug]` | One sample employer's profile: identity, overview, open roles | Candidates researching a specific employer | Bespoke `dc-company-hero` (job-detail header language), `JobRow` list, facts aside (`card-outline`), `Reveal`-animated related `CompanyCard`s, CTA | `features/companies/data.ts` (`getCompany`), `features/jobs/data.ts` (`jobsAtCompany`) | Static server component; `robots: noindex` (individual sample profile, mirrors job-detail's own precedent) | Verified employer profile CMS; real "claim this company" flow |
| `/categories` | Distinctive category hub: 6 featured + full A–Z taxonomy | Candidates orienting by field | `PageHeader`, `Reveal`-animated feature `CategoryCard` grid, `CategoryIndex` (quick filter, sticky group index ≥1024, `category-chip-grid` per group) | `features/categories/data.ts` (featuredCategories, categories, categoryGroups) | Categories are real ADDOZ taxonomy; role counts are sample-labelled | None — taxonomy is real; only role counts are illustrative |
| `/categories/[slug]` | One category's roles with lightweight filters | Candidates browsing a field | `PageHeader` (group + description), job type / career level `chip` groups, `FilterBar` + sort, Flip-reflowed `JobCard` grid, `EmptyState`, related `CategoryCard`s | `features/categories/data.ts`, `features/jobs/data.ts` (`jobsInCategory`, `filterJobs`) | `generateStaticParams` for every category incl. zero-role ones (e.g. Agriculture & Farming) | Live jobs API filtered server-side by category |
| `/locations` | Location hub: featured areas + every area grouped by state | Candidates browsing by area | `PageHeader`, `Reveal`-animated large `LocationCard` grid, plain data-driven `states.map` → `LocationCard` grid per state | `features/locations/data.ts` (featuredAreas, states, areasInState) | Fully static/server-rendered; honest note that only Lagos + Ogun exist today | More states/areas — architecture is grouped + data-driven, no hard-coded markup |
| `/locations/[slug]` | One area's roles, categories hiring there, nearby areas | Candidates browsing a specific area | `PageHeader`, job type chips, `FilterBar` + sort, Flip-reflowed `JobCard` grid, `EmptyState`, compact `CategoryCard`s derived from area's jobs, `Reveal`-animated nearby `LocationCard`s | `features/locations/data.ts` (`getArea`, `nearbyAreas`), `features/jobs/data.ts` (`jobsInArea`) | `generateStaticParams` for every area | Live jobs API filtered server-side by area |

## Employers and auth

| Route | Purpose | Audience | Components | Content source | Prototype state | Future backend dependency |
|---|---|---|---|---|---|---|
| `/for-employers` | Sell the employer offering: value prop, hiring workflow, posting form preview, talent discovery, applicant management, testimonial, closing CTA | Prospective employers | `MagneticButton`, `ActionButton`, `SectionHeading`, `Reveal`, `SampleTag`, `ScrambleLabel`, `next/image` | `employerProposition`, `testimonials` (Grace Nwachukwu) from `features/content/testimonials.ts` | Static content page, no forms | None — fully static |
| `/for-employers/post-a-job` | Public "post a job" flow: 3-step form with live preview, draft autosave, progress, and "what happens next" | Employers ready to post | `PageHeader`, `JobPostForm(context="public")` | `features/categories/locations/jobs` data | UI-only; nothing saved/published; draft autosaves to `localStorage` | Real job creation, employer account, publishing pipeline |
| `/auth/login` (+ `?role=employer`) | Sign-in prototype, employer wording when `role=employer` | Returning users/employers | `LoginForm`, `PasswordField`, `ErrorSummary` | Hand-authored copy | Loading → honest "not connected" result with links onward | Real auth/session backend |
| `/auth/register` (+ `?role=employer`) | Candidate/employer registration | New users | `RegisterForm`, `ChoiceCards`, `PasswordField`, `PasswordStrengthMeter` | Hand-authored copy | Loading → routes to `/auth/verify?email=…`; no account created | Real account creation, email delivery |
| `/auth/verify` | 6-digit email verification | New users mid-registration | `VerifyForm`, `OtpInput` | Hand-authored copy | Any 6 digits succeed; resend countdown is cosmetic | Real code generation/delivery/check |
| `/auth/forgot-password` | Request a password reset | Users locked out | `ForgotPasswordForm` | Hand-authored copy | Non-revealing success message; no email sent | Real email delivery, token issuance |
| `/auth/reset-password` | Set a new password | Users from a reset link | `ResetPasswordForm`, `PasswordRequirements` | Hand-authored copy | Validates + shows success → login; nothing stored | Real token validation, password storage |
